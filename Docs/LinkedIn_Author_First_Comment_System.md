# Author First-Comment System

Companion to `LinkedIn_Comment_Intelligence_System.md` — but a different thing. That file governs commenting on *other people's* posts. This file governs the ONE planned comment the account owner (Umesh) leaves on his *own* post after publishing it.

Kept as its own file rather than folded into Comment Intelligence because the audience, purpose, and timing are different: this is author-on-own-post, done once, right after publish; Comment Intelligence is author-on-others'-posts, ongoing, targeted by creator category.

---

## Purpose

Every published LinkedIn post should have ONE planned first comment from the author's account when there is a genuine additional point to add.

The purpose is:
- Extend the conversation
- Add useful context
- Clarify a point
- Add a caveat
- Share an additional example
- Add a relevant detail
- Ask a meaningful follow-up question
- Give readers another reason to engage

**IMPORTANT:** The first comment must NOT exist merely to manipulate notifications, artificially inflate engagement, or create fake activity. It must add genuine value.

---

## First Comment Rule

For every post, determine whether an author comment would add value.

IF YES: prepare exactly ONE first comment.

IF NO: mark **FIRST COMMENT = NOT NEEDED**.

Do not force a comment just because the system expects one.

---

## First Comment Content

Good first-comment formats:
1. Additional context
2. Important caveat
3. Real example
4. Additional observation
5. Supporting evidence
6. Practical implementation detail
7. Genuine follow-up question
8. Clarification that was intentionally left out of the main post
9. A useful detail that would have made the main post too long

The comment should feel like: *"One more thing worth mentioning..."* — not: *"Hey everyone, what do you think?"*

---

## Do Not Repeat the Post

The first comment must NOT simply summarize the post.

**BAD:**
Post: "Reviewable automation is better than blindly autonomous automation."
Comment: "Exactly. Reviewable automation is important because humans should be able to review AI decisions." — This adds nothing.

**BETTER:**
"One detail I left out: the review step doesn't need to mean a human checks everything. We usually want the system to surface only the low-confidence exceptions." — This extends the original idea.

---

## No Generic Engagement Bait

Do NOT use first comments such as: "Thoughts?" / "Agree?" / "What do you think?" / "Let me know your thoughts." / "Anyone else?" / "Who's experienced this?" — unless the question is genuinely relevant to the post and likely to create a useful conversation.

---

## One Comment Only

Default: ONE author comment per post. Do not create multiple artificial comments from the author's account just to increase activity. Additional replies are allowed ONLY when responding naturally to actual people.

---

## Timing

Prefer posting the author comment shortly after the post is published, when it genuinely contributes context. Do not delay or post empty comments solely to manufacture an engagement pattern.

---

## Human Writing

The first comment must follow the same anti-AI rules as the main post (per `LinkedIn_Operating_System.md`'s human-writing rules). Avoid repetitive: "One thing worth noting..." / "The interesting part..." / "The key takeaway..." / "Here's the thing..." / "This is important because..." / "I'd rather..." / "Most people..."

Do not use the same first-comment structure on every post. Vary naturally.

---

## Source / Evidence

If the first comment contains numbers, statistics, claims, results, technical facts, customer information, or project information — verify them using the same evidence standards as the main post (Proof Inventory / "could not verify" discipline). Never invent supporting evidence.

---

## First-Comment Strategy by Post Type

**TOFU:** Possible — additional personal detail, context, short follow-up observation, genuine question.

**MOFU:** Possible — implementation detail, example, caveat, practical next step.

**Authority / Proof:** Possible — additional evidence, technical detail, decision context, what was intentionally left out, limitation of the result.

**Creator Breakdown:** Possible — additional lesson, why the creator's strategy matters, another example, important nuance.

---

## Pre-Publish Check

Before publishing:

```
FIRST COMMENT: ✅ Prepared / N/A — Not needed

If prepared:
[ ] Adds new information
[ ] Does not repeat the post
[ ] Is relevant
[ ] Is human
[ ] Contains no fabricated claims
[ ] Is not engagement bait
[ ] Is not promotional without reason
[ ] Is not copied from another creator
```

This check is folded into `LinkedIn_Verification_Gate.md` as a conditional item — see that file's checklist.

---

## Analytics

Track the author-comment strategy as an experiment, per `LinkedIn_Self_Learning_System.md`'s discipline. Record:
- Whether first comment was used
- Comment content type
- Comment timing
- Post impressions
- Comments
- Replies
- Profile views
- Followers gained
- Meaningful conversations

Do not assume the first comment caused higher reach — treat it as a testable variable, logged in `LINKEDIN_LEARNING_MEMORY.md`'s Comment Learnings section once real data exists.

---

## Important Policy Rule

Do NOT automate author comments through scripts, browser extensions, bots, or third-party automation. The comment should be manually posted by the account owner. LinkedIn explicitly limits the visibility of excessive or automated comments, and its current guidance emphasizes authentic conversations.

This system prepares the *content* of the first comment as part of the post-verification package — it does not post it. Posting it is a manual action by Umesh.

---

## Core Rule

**MAIN POST:** Start the conversation.
**FIRST AUTHOR COMMENT:** Add another useful layer.
**REPLIES:** Continue the real conversation.

Never manufacture engagement.
