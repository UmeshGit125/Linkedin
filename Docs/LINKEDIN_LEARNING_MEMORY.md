# LinkedIn Learning Memory

The living scoreboard for this LinkedIn system. Every assumption in every other file is a hypothesis until this file says otherwise — and this file only says otherwise when real analytics from real published posts are provided.

**Companion to:** `LinkedIn_Self_Learning_System.md` (the method this file records results for), `linkedin_content_system.xlsx` (the per-post Content Database these summaries are drawn from), `LinkedIn_System_README.md` (read-order and update rules).

**Hard rule, same as every other file:** never invent a result. A row stays TBD until a real number exists. A missing number is a reason to leave the row empty, never to estimate.

---

## How this file works

- It is **never recreated** — only updated, one row at a time.
- Nothing enters it without real analytics from published posts. A hunch, a preference, or an intuition from writing the draft is not a learning.
- Every learning carries a confidence level (LOW / MEDIUM / HIGH) as defined in `LinkedIn_Self_Learning_System.md`. Until a variable has been tested across a full 9-post batch — and ideally repeated across two — nothing here is above LOW.
- A learning that gets contradicted later is **marked superseded, not deleted** (same pattern used for the 5-post/day → 3-post/day change in `LinkedIn_Master_System.md`).
- `LinkedIn_Self_Learning_System.md` is the only file allowed to read this and change behaviour. Nothing here overrides the no-fabrication rule.

## What to update, and when

| After this happens | Change here |
|---|---|
| A batch publishes and analytics are provided | Add the Batch Log row, fill the relevant What Worked / What Did Not Work rows, assign a confidence level |
| The same direction shows up across two batches | Promote the confidence level; note the promotion with the date |
| A timing pattern gets enough evidence to matter | Fill the Timing Learnings row; `LinkedIn_Scheduling_System.md` changes only if the baseline itself needs revising |
| Umesh confirms or corrects a positioning/audience assumption | Update Audience Notes, marked as user-confirmed rather than data-derived |
| A learning is later contradicted | Mark it superseded in place, don't delete it |

Filling this file is not a task done at the end of a batch "to have something in it." An empty row is correct until a real number exists to replace it.

---

## Core rule

**ASSUMPTION < OBSERVATION < ONE BATCH < REPEATED BATCH.** Nothing crosses a confidence level without the evidence behind it. One post is not a pattern, one batch is not a law, and a plausible-sounding number that was never measured is worse than a TBD.
